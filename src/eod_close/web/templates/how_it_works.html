How it works

A real bank file can have tens of thousands of entries, so the engine has to be fast as well as right. This page shows why it is built the way it is, by racing it against the obvious approach on days of different sizes.

  • Naive pairwise: for each bank entry, search the whole ledger for its partner. Twice as many entries means about four times the work (O(n²)).
  • Engine: first builds indexes of the ledger, like the index at the back of a book, so finding a partner is a quick lookup instead of a search. Twice as many entries means only a little over twice the work.

Pick some sizes and run the race. On tiny days the naive approach can win, because building the indexes has a fixed cost; watch how the gap opens as the days grow. Times are measured live on this server, so they vary from run to run.
